# Demand-directed materialization

Status: implementation support module, 2026-11-04. Runtime integration is owned by the learning flow. This document does not claim a new model run, fresh acquisition, independent task success, or formal proof.

The authoritative contracts and docstrings are in `src/oak/materialization.py`. They describe executor-derived evidence demands, exact selectors, bounded traversal needs, retained source coverage metadata, missingness, and materialization cache identity. They do not replace the frozen ontology or the existing function executor.

`derive_demand` reads actual frozen function operators and bound arguments. It retains schema-required properties and identity, requests predicate and aggregate fields, and conservatively widens unresolved runtime selectors. The existing acquisition result path `entities_by_type` supplies type information without a domain registry. `slice_graph` projects genuine records and their provenance, retaining requested relationship endpoints. It never establishes source completeness from the fact that a graph was supplied.

The user's autonomy correction supersedes the earlier proposed mandatory coverage gate. `assess_sufficiency` is an informational result. Unknown completeness, missing population evidence, and generated self-checks do not prohibit function execution or agent answers. The planner receives the gap and can autonomously acquire, materialize, compute, or answer within its budget. Independent task assessment remains separate. Structural graph validation and frozen-kernel constraints remain enforced by the existing executor.

No custom domain verifier or runtime adapter registry was added. Optional trusted coverage receipts can describe independently established facts when available. Model claims and generated checks remain distinct evidence bases and cannot upgrade themselves to independent source completeness. Snapshot completeness is distinct from source-population completeness.

The twelve module tests use checksum-verified exported weather artifacts. They execute real lookup/projection and arithmetic functions on a retained graph and a smaller derived graph, compare results, preserve optional property reads through result and argument paths, validate traversal endpoints and required properties, distinguish null from unmaterialized data, reject stale cache/schema bindings, and ensure subset counts are not mislabeled complete. Repeated source IDs are deduplicated and mixed known/runtime traversal frontiers remain conservatively represented. An optional source-comparison test reads the existing weather parser and actual source temperatures; it is a test observation, not a runtime dependency or a new benchmark execution.

Known limits: demands whose property names, acquisition arguments, or traversal seeds depend on unresolved step outputs are conservative and marked unknown. The module does not interpret arbitrary natural-language existence intent, synthesize pagination arguments, implement freshness reconciliation, or promise that a model extractor followed every demand. Those are caller-level strategy and observation concerns. It preserves the entire frozen schema in extraction context because removing declarations could invalidate inheritance or constraints; selective materialization is controlled by the demand, not by mutating S.
