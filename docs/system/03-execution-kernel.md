# Trusted execution kernel and isolation

The kernel owns the only route from a proposal to a task effect. Follow the transaction and crash protocol in [execution-trace-protocol-v1.md](../../execution-trace-protocol-v1.md). This document defines the checks and process boundary around it.

**Admission algorithm.** Resolve the proposal to one pinned contract and binding. In this order: validate message and arguments; verify the authenticated caller's episode; resolve account/environment/resource scope; check current credential binding and tool/schema revision; evaluate state/evidence freshness and operation preconditions; check permitted workflow edge; check effect/concurrency capability; check budget/deadline; commit the allow/deny record and reservation. Every check yields a named rule receipt, including skipped checks after a decisive failure. An exception is `POLICY_ERROR` and denies dispatch.

Authority uses authenticated principal bindings and protected allowlists/predicates, not labels extracted by an LLM. Resource IDs extracted from text are lookup candidates. Resolve them to scoped backend objects before permitting effects. Reads also require scope. Preconditions referencing external mutable state require a declared backend conditional write/transaction or exclusive isolated environment; otherwise deny the state-sensitive mutation `CAPABILITY_UNAVAILABLE`. A best-effort precheck cannot be marketed as atomic enforcement.

Revalidate ephemeral permission/state at dispatch. Consume an admission only once, and only after its durable dispatch intent commits. Execute outside the database transaction. Preserve the exact effect certainty and record any independently verified postconditions. A compound function's admission restricts descendants but does not preapprove their calls.

**Effect classes.** `PURE` uses admitted local evidence and produces no environment effect. `READ` can access external state under its declared cost/side-effect contract. `WRITE` changes scoped state. `ASYNC_WRITE` returns a pending handle. `COMPENSATE` is a separate operation with a link to an earlier effect. Idempotency is `NONE`, `NATURAL`, or `KEYED`, with scope/expiry stated. Retrying always needs fresh admission; the kernel never infers idempotency from an HTTP verb or a tool name.

The retry controller has at most three physical tool attempts per operation, including the first. Use declared server backoff when it fits the deadline, otherwise delays of one and two seconds. Apply only to contract-approved transient outcomes; authentication, validation and policy errors are not transient. Unknown writes enter reconciliation. Poll async operations at 1, 2, 4, 8, then 10-second intervals, maximum ten polls and always within episode/operation budgets. After that, suspend with the pending handle; no speculative replacement mutation. Every poll is an admitted operation.

**Process arrangement.** The trusted scheduler/ledger writer and privileged adapter live outside generated-code workers. The CLI runs in its own restricted model process. Generated Python domain functions run inside a Linux OCI worker with no network, no backend credentials, no host filesystem mount, read-only package/runtime, bounded tmpfs, non-root UID, dropped capabilities, no-new-privileges, process/memory/CPU/wall limits and a restricted system-call policy. The worker speaks length-prefixed UTF-8 JSON over a dedicated inherited pipe. Kernel dispatch binds the pipe to the parent operation; worker-supplied IDs cannot impersonate another scope.

Allowed worker RPC methods are `operator.call`, `tool.call`, `evidence.read`, `artifact.submit` and `result.submit`. Each uses a closed method schema, parent-operation scope and size limits. Tool calls must appear in the function's declared effect footprint and the task manifest. Operator calls cannot introduce new operator names. `artifact.submit` writes staged bytes through the trusted artifact writer; it grants no general path access. `result.submit` carries a proposed result, not an authoritative success flag.

A worker may import only the prebuilt runtime, its package and an explicitly reviewed dependency lock. Import allowlists, AST checks and type checks are early diagnostics; the OS boundary remains mandatory. No package install, dynamic dependency resolution, shell tool, socket capability, host Docker socket or writable policy/evaluator mount is exposed. A worker attempting a forbidden path/API receives a denial receipt and fails its conformance case.

Bootstrap resolves a Python 3.12 Linux base image to a digest and builds the runtime image with a locked dependency set. Record that digest. If an OCI runtime or required isolation control is missing, fail the untrusted-code readiness gate. Scripted in-process fixtures may continue as tests labeled unenforced; they cannot count as controlled-agent benchmark evidence. The host's current OS and installations are not assumed to meet this gate.

**Budget accounts.** One experiment root funds episode exploration, episode finalization, diagnostics and repair/evaluation subaccounts. Limits are nonnegative immutable quantities; allocations transfer existing allowance. Consumptions and outstanding reservations are distinct. Resuming or creating a branch changes IDs, not total authority. Reject an operation if its conservative reservation cannot fit. Strict token mode rejects unbounded adapters. Observed mode records reported/estimated usage and makes no hard token/currency claim. Wall limits cannot prove that remote work ceased, so unknown effects/charges remain outstanding.

Every account labels enforcement `HARD`, `SOFT` or `OBSERVE`. Admission invariants apply to hard bounds; soft/observed usage still records actual overrun rather than dropping a truthful receipt. If a backend exceeds a declared hard bound, record actual usage and the contract violation, stop further admission and fail the affected control check. Remaining allowance is clamped at zero; historical use is never rewritten to make the limit appear respected. The controller precomputes a finite schedule and funds its subaccounts before launch; an unfunded stage returns `BUDGET_EXHAUSTED` rather than silently increasing the experiment cap.

**Failure atomicity.** Ledger unavailable before intent means no invocation. Failure after intent means reconciliation unless a committed receipt proves the effect outcome. Artifact publication precedes committed references. Repeated delivery cannot settle twice. Resource revision conflicts return a conflict observation and require a fresh read. Failed compound functions retain successful child effects; a compensation plan is separately admitted. The only implicit rollback is an actual backend transaction explicitly declared by the adapter.

**Resume and fencing.** Recover under an exclusive environment-owner lock. Kill/join local workers; verify the prior owner cannot keep dispatching. Recover the latest valid checkpoint and replay later ledger events. Reconcile all dispatch-started/pending operations before actor mutations. Read back package, policy, principal and tool identities; drift suspends the binding. Never restore an old budget snapshot without replaying subsequent consumption. Native environment snapshots may be used only according to verified adapter restore capabilities.

**Security/integrity tests.** Attempt forged authority fields, cross-episode artifact reads, path traversal, schema substitution, stale-state writes, internal unmanifested tool calls, raw sockets, subprocess/file bypass, evaluator access, duplicate dispatch and ledger tampering. Success means actual prevented access/effects observed from outside the worker, not a polite model refusal. See `KRN-*` acceptance cases.
