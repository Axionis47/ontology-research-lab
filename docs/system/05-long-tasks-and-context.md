# Long tasks, evidence acquisition and bounded context

The ledger is the history. The graph is a versioned view of admissible facts. The context is a selected input for one model call. None substitutes for the others. This document specifies exactly how a fact reaches the actor or judge.

The active [one-family pilot](11-narrow-training-and-inference.md) uses the bounded context packer and direct evidence references first. Large-document indexing, long-episode compaction and multi-hop graphs are deferred extensions. All numeric maxima are further restricted by the active profile; contextual limits do not require manufacturing a large task to exercise every feature.

**Evidence ingestion.** On every tool result: publish the raw/protected artifact; validate the response contract; extract structured records using pinned mappings; create evidence entries with source IDs, observed time/revision, JSON pointers or text offsets, visibility, completeness and hash; update graph facts and dependency indexes; mark any conflicts or superseded facts. Keep binary/media artifacts by reference; if the selected model cannot inspect the media type, use an explicitly versioned supported extractor or return `CAPABILITY_UNAVAILABLE`. Text extraction is a transformation with its own provenance, not the original file.

For long text, normalize line endings in a derived artifact, retaining the original. Split by section/paragraph boundaries up to 1,024 estimated tokens per chunk with 64-token overlap; if a paragraph is larger, split at sentence then byte-safe text boundaries. Store original and derived offset mappings, section path and chunk hash. Structured tables paginate by rows with repeated schema headers. A table total requires complete pagination or an authoritative source aggregate.

Index metadata and normalized text in SQLite FTS5 with stable ID/revision fields; probe availability at bootstrap. If unavailable, use parameterized token-match SQL against the same scoped index and record the index implementation. Neither mode executes model-provided SQL. Initial search is lexical and structural; vector retrieval is not required or silently introduced.

**Acquisition before each decision.**

1. Start with unresolved public requirement IDs and their explicit dependency keys: entity IDs, source fields, relation types and expected observation type. Seed these from validated task slots and previously resolved entities, not an unrestricted rewritten user goal.
2. Collect exact referenced evidence from the last receipt, required dependencies, pending effects, contradictions and the actor's explicit revisit request. Resolve only within scope and split visibility.
3. For unresolved keys, search the authorized index using exact entity/requirement tags first. Then use Unicode-normalized casefolded query tokens from the requirement text and validated slots. Rank exact IDs first, field/tag matches second, lexical score third, freshness next, stable ID last. Return up to 20 hits with locators, completeness and availability.
4. Select up to four evidence reads for this step, prioritizing missing preconditions, contradictions, current obligation dependencies, then exploratory alternatives. An exact read accepts artifact/evidence ID plus JSON pointer or bounded text/row range. It returns the excerpt, source revision, surrounding field/section header and a continuation cursor. Each external refresh is a separately admitted tool call. Each local read is logged and bounded.
5. If the index contains no required fact, consult the task's registered evidence-provider mapping from requirement/field to tool/query template. Fill only validated slots, admit that read, ingest its result, and repeat within the four-read budget. If no provider exists, return an evidence gap with missing keys; the actor may choose another legal path or request input. Do not fabricate a source or assume the search established absence.
6. Construct context from the resulting cards. Record the selected, excluded and stale IDs and selection reasons in a context manifest. A failed search/read is visible as a typed result with scope and completeness, not an empty success.

This procedure never bypasses the tool manifest. Search results do not grant access to their artifacts. Source discovery and reading are distinct metered operations.

**Freshness and invalidation.** A deterministic environment snapshot revision remains valid until an operation changes relevant state. External sources require a contract-specific TTL or backend revision. If neither exists, evidence is observation-time-only: re-read before a state-sensitive decision, and require backend concurrency control for mutation. Track reverse dependencies from source fact to derived fact, requirement check and context item. A new conflicting revision invalidates all reachable derived claims; recompute them when needed. Keep earlier evidence for diagnosis but label it stale in any later observation.

**Packing algorithm.** Compute available input as the minimum of the role input cap and any verified provider window minus output reservation and headroom. Unknown provider window is explicitly unverified and uses the configured adapter input cap, without an exact effective-context guarantee. Use a verified tokenizer when available; otherwise record the estimator and byte limit. A provider overflow is a failure receipt, never an unlogged auto-truncation.

The pinned block contains goal/constraints, protocol/schema, relevant tool contracts, current budget/permission summary, outstanding effects and exact public requirement state. This block cannot be summarized away. Reserve it first. Then add the latest observation and up to four recent steps. Then add up to twelve evidence cards, each up to 256 estimated tokens, selected by the acquisition priority above. Add older context entries only if capacity remains. These are maxima, not promises that every maximum fits simultaneously.

Do not send the entire schema bundle to a model. Resolve only that role's output schema and its transitive referenced definitions. Render a versioned compact field/type contract and the currently selected tool schemas; retain the full validator schema hash in the context manifest. If the provider supports an enforced output grammar, supply the same resolved schema through that capability and record its identity. The actual rendered text/grammar is captured. A compact rendering never changes runtime validation or expands allowed fields.

Shrink optional material deterministically in this order: old exploratory cards, old success receipts already represented by checked facts, older recent-step detail, duplicate excerpts. Preserve their pointers in the manifest. If the pinned block plus latest necessary result does not fit, narrow the task-visible tool subset using verified workflow/state and required dependencies, preserving a manifest-bound tool-discovery action. That action can expose another permitted subset without increasing authority. If it still does not fit, return `CONTEXT_OVERFLOW`; never delete policy, unresolved effects or user constraints to make the request fit.

**Compaction is a controlled state change.** Maintain a context ledger of item IDs with `kind`, exact statement, evidence refs, dependency revision, validity, first/last step and provenance. Kinds are goal constraint, checked fact, hypothesis, decision, artifact, failed attempt, open obligation and next-action suggestion. Goals, scope, budget and checked facts are written from runtime records. Actor summaries can propose hypotheses/suggestions only. At a packing overflow or a 20-step checkpoint, compact eligible older details into source-linked entries; merge by stable item identity. Do not repeatedly summarize the entire prior summary into a new free-form paragraph.

V1 compaction is deterministic from receipts and requirement state. Model-written narrative compaction is disabled in the profile; enabling it later requires a separate output contract and regression gate. Verify that all unresolved obligations/effects, latest artifact revisions, decision-relevant conflicts and referenced evidence remain reachable before committing a replacement context. The old context remains addressable by hash.

**Revisiting and very long work.** A revisit reads the earlier step's original context and cited evidence, then checks current validity and shows changed/unchanged facts. It never pastes an old tool success into the current state as though the effect just occurred. Long documents are read page/chunk by page/chunk with coverage intervals, not repeatedly prefixed into every prompt. Checkpoint at every completed step and after any durable effect receipt; context segments are logical groupings for inspection, not fresh episodes or quotas.

**Judge access uses the same evidence gateway with different visibility.** A judge may inspect authorized train-only diagnostics and original actor contexts; it does not automatically inherit evaluator secrets or entire archives. For each evidence read, log who requested which locator, what bytes were returned and what was omitted. A claim cites the original record/excerpt, not a summary's assertion that some evidence once existed.

Completion tests `LONG-01` to `LONG-04` insert an early constraint, a mid-task contradiction, a changed artifact, and an unresolved effect across multiple compactions. Continuing and judging must recover each exact source and respect the latest valid state. Coverage checks also detect chunks that were never read. A compact summary that sounds plausible but fails these probes is rejected.
