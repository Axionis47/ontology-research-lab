# Domain computation, operator contracts and task surfaces

The fixed operator membership is [oak-nine-operators.md](../../oak-nine-operators.md). This document supplies our implementation semantics; it does not claim these details are copied from OaK code. OaK motivates constructing schemas/functions with training feedback and freezing them during inference. [Paper](https://arxiv.org/html/2608.22974v1#S3).

**Active implementation subset:** follow [the narrow protocol](11-narrow-training-and-inference.md). Begin with raw-tool inference and ordinary admitted records. Implement at most one helper and up to three operators only if the comparison warrants it. The nine entries below fix compatibility semantics; they do not require building or running all nine. ALFWorld/tau2 and larger graphs below are future adapter references, outside the current milestone.

**Package layout and initial construction.** A package contains `manifest.json`, `schema.json`, `mappings.json`, `functions/*.py`, `function_contracts/*.json` for input/output contracts, dependency lock and fixture tests. Earlier optional `workflows.json` and `context_items.json` remain compatibility artifacts, not automatic learning targets in the active phase. The manifest lists every file digest, supported surface/version, operator runtime hash and declared effects. It contains no credentials, evaluation solutions, task-specific answer tables or permissions. Package content is immutable once hashed. The [computational protocol](12-computational-learning-protocol.md) separates task data and obligations from reusable procedures for handling relationships and constraints.

To construct the seed: inventory allowed tool interfaces; read authorized train tasks and source examples; propose entity/relation/property types with examples and provenance; compile constraints; propose mappings from tool output JSON pointers; implement a small set of typed functions using the locked operators and admitted tools; author fixtures from train data; run schema, mapping, function and enforcement checks; archive the resulting package as the seed. Record whether each file was engineer-authored or model-proposed. No inferred business permission becomes a protected rule without an explicitly authored policy binding. Unavailable construction-model access blocks model-generated construction; a clearly labeled engineer-authored seed may still support runtime tests.

**Graph representation.** Use typed entity, relation, property and evidence tables in the kernel's SQLite database, updated transactionally with graph-change events. IDs include source namespace and primary key; equal display names do not merge identities. Relations have IDs, endpoints, type, source refs and validity intervals. Property values distinguish missing, explicit null and known values. Each derived fact records its input evidence IDs and transform/package version. Maintain indexes on namespace/type/key, relation type/endpoints, and source/evidence dependency. The actor graph includes only evidence available through permitted observations, never hidden evaluator databases.

Schema checks cover declared entity/relation types, property types, relation domain/range, disjoint types, mandatory properties where the record declares completeness, cardinality and declared uniqueness. They return violations with affected IDs and source refs. Incomplete data returns unknown for checks requiring closed-world completeness. V1 uses these explicit deterministic constraints, not an unimplemented claim of full OWL/HermiT reasoning.

**Shared operator contract.** Inputs include a scoped immutable `graph_revision`, typed parameters and bounds. The runtime injects scope; the model cannot expand it. Outputs include typed rows/entity IDs, used evidence refs, completeness (`COMPLETE`, `PARTIAL`, `UNKNOWN`), unknown/excluded counts, deterministic ordering and continuation cursor where applicable. A partial result cannot justify a whole-set count or absence claim. Ordering ties use stable entity/relation IDs. Cursors bind query hash, graph revision and scope; changed revisions invalidate them.

| Operator | Inputs and computation | Missing, ambiguity and limits |
| --- | --- | --- |
| `extract_runtime_slots` | Text/evidence ref plus a schema of declared slots; a metered model call proposes values with exact source offsets; deterministic validator checks types and cited spans | Unsupported/ambiguous slot remains unresolved with alternatives; no invented defaults or authority; no hidden extra model call |
| `lookup_entities` | Type plus exact IDs/keys/typed property predicates, or explicit fuzzy query; exact lookup first, optional Unicode-normalized casefolded text token matching scored by fraction of query tokens matched | Return ranked candidates; fuzzy matches never establish unique identity for a write; ties remain ambiguous; paginate after the configured bound |
| `traverse_relations` | Start IDs, allowed relation types, direction, maximum hops; breadth-first traversal with visited-ID deduplication | Missing endpoints are reported; cycles terminate through visited sets; stop at entity/edge bounds with `PARTIAL` and cursor |
| `project_properties` | Entity IDs and declared property names; return rows retaining identity and type | Missing and null remain distinct; no implicit coercion; rows keep source refs |
| `filter_property_categorical` | Typed property and include/exclude value set with explicit any/all semantics for multivalued fields | Equality uses schema normalization only; unknown values excluded from matches and counted; alias `filter_categorical` resolves to the same implementation |
| `filter_relation_connected` | Entity IDs, anchor IDs, allowed relation types/direction and any/all anchor requirement | One-hop connectivity unless the function explicitly composes traversal; unknown completeness prevents proving disconnection |
| `filter_numeric` | Property, comparison/range, units and inclusive/exclusive bounds | Parse canonical decimal strings with decimal arithmetic; reject incompatible units and non-finite values; missing counted as unknown |
| `filter_set_overlap` | Multivalued property, comparison set and any/all/minimum intersection rule | Normalize/deduplicate values by schema; empty query with all-match is true, any-match false, minimum requires declared integer; missing set is unknown |
| `aggregate_values` | Rows, grouping fields, operation `count/sum/min/max/mean`, explicit `count_rows` versus `count_values`, distinct key and missing policy | Counts are integers, other numeric outputs canonical decimals; empty count is zero, empty min/max/mean unknown; partial input marks aggregate partial; no silently complete result |

Default graph bounds are in the profile; a function may declare stricter ones. Larger authorized queries use explicit pagination, each metered. Decimal rounding uses the property's scale and round-half-even; absent scale preserves exact sums and returns mean at the profile's 28-digit precision, recorded in the output contract. Time values are UTC timestamps with original source timezone retained when relevant. Comparison across incompatible calendars/units fails validation rather than coercing.

**Mappings and functions.** Each mapping identifies the source contract hash, source JSON pointer, target type/property, conversion rule, missing policy and provenance rule. Validate raw response first; then map applicable fields. Preserve raw bytes and unresolved fields separately. Contradictory facts coexist with conflict status until a declared source-precedence rule or new evidence resolves them. A mapping does not overwrite history.

A function has typed inputs/outputs, preconditions, maximum child operations, operator dependencies, tool effect footprint, completion/postcondition checks, timeout and partial-result semantics. It runs in the document 03 worker. Child calls are admitted individually. A function can return success only according to its output contract; the kernel separately checks its claimed effects. Workflow templates may suggest ordering and allowed backtracking. Protected policy transitions remain outside editable templates. A cyclic workflow must include a state/evidence change or bounded retry condition; the scheduler's budgets remain the final bound.

**Tool onboarding is a concrete pipeline.** Bind server/account/environment; enumerate all discovery pages; store exact names/descriptions/input/output schemas and explicit schema absence; fingerprint the inventory; classify effects and unsupported guarantees from documentation/source/probes; build an `OperationContract`; run read/write/error/timeout/idempotency fixtures where supported; publish a task-specific selected-tool manifest. Failure at any stage leaves the tool unavailable with a reason. A newly discovered tool never appears silently in an existing episode. Recheck authentication and relevant schema fingerprints on resume. See [MCP invariants](../../mcp-tool-onboarding-invariants.md).

**Surface adapter interface.** Each adapter implements `load_task`, `create_environment`, `observe_initial`, `list_contracts`, `execute_bound_action`, `inspect_postcondition`, `save_snapshot`, `restore_snapshot`, `native_terminal`, `complete_task`, `evaluate_terminal` and `close_environment`. Unsupported snapshot/verification operations return a typed capability result. They are never successful no-ops. Each episode has an isolated environment directory/process and explicit environment ownership; no shared mutable simulator across episodes.

AppWorld is first, pinned at `42b5bcf3cd334fee33f0c37c02070a9f5807add5`. Translate an admitted typed request to a fixed adapter call to the selected API. Do not pass arbitrary actor-generated Python to `world.execute`. If code-shaped invocation is required, build it from a validated allowlisted callable and serialized data, never string-interpolated executable fragments. Preserve native API/environment logs, native interaction counters and kernel child-operation counts. Correlate native requests to kernel attempts in the trusted adapter, including helper calls. Any native call outside the declared footprint fails the adapter conformance test. [Reference function-calling agent](https://github.com/StonyBrookNLP/appworld/blob/42b5bcf3cd334fee33f0c37c02070a9f5807add5/experiments/code/simplified/function_calling_agent.py).

AppWorld's evaluator is terminal-only and privileged. Public checks come from user-visible obligations and API contracts; they cannot expose hidden tests. Save/load capabilities are verified for database state, RNG, time, interaction count and interpreter state separately. Missing capabilities disable claims of exact replay, and fresh isolated episodes are used for candidate comparisons.

ALFWorld is second. Translate typed actions to its actual action vocabulary, preserve admissible-command observations and native terminal reward, and keep exploration/backtracking valid. Pin release/data/split hashes during adapter bootstrap. No assumption that simulator snapshots exist. tau2 is third, using its pinned native conversation/user-simulator protocol and evaluator; do not reuse AppWorld completion or counters. Each new adapter must pass the same core schema, trace, scope, unknown-outcome and budget cases before comparison.

External MCP business applications use the same adapter contract, but are outside native benchmark claims until their own completion checks and policy oracle exist. Unknown effects or missing atomic state enforcement make affected writes unavailable. Read-only exploration can still run when authorized and its limitations are explicit.
